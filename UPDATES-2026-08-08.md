## 2. Fixed: skill-gap PDF upload never worked

**Symptom:** every PDF upload failed with *"The model did not return a parseable recommendation."*

**Root cause:** `backend/services/recommender.py` told the LLM to "match the IntakeResult schema" **without ever showing it the schema**. The model invented its own field names (`name` instead of `learner.full_name`, `program` instead of `recommended`…), so validation always failed.

**Fix:**
- An explicit `OUTPUT_FORMAT` JSON skeleton is now embedded in the system prompt.
- A one-shot **self-repair retry**: if validation fails, the model is shown its own output plus the validation errors and asked to re-emit corrected JSON.

**Verified:** `sample-documents/skill_gap_report.pdf` now produces correct drafts — Aisha Osei → *Data Privacy Practitioner* (90% confidence), Viktor Lindqvist → *ISO 27001 Security Framework* (92%).

## 3. Fixed: "Meeting mode is not configured yet" was hiding the truth

The `.env` keys were set all along. The real failures were:

1. **AgentCall account has zero credits** (API returns 402 *insufficient credits*).
2. The **`loca.lt` tunnel in `AVATHAR_PUBLIC_URL` was dead** (quick-tunnels expire on every restart).
3. `vite.config.js` `allowedHosts` only allowed `.trycloudflare.com`, silently blocking other tunnels.

**Fixes:**
- `/meetings/start` now **pre-flights the tunnel** and returns exact instructions if it's down.
- AgentCall 402/401 map to plain-English messages (top-up link / bad key).
- `frontend/src/api.js` now surfaces the backend's `detail` message on **every** request app-wide.
- Aarav **speaks the actual reason** instead of "not configured yet".
- `allowedHosts` now accepts `.trycloudflare.com`, `.loca.lt`, `.ngrok.app`, `.ngrok-free.app`.
- A fresh cloudflared tunnel was started and saved to `.env` (remember: it dies when cloudflared stops).

**Researched free credits:** AgentCall gives new accounts 6 free hours (this account's are used up). Options: ask their support for demo credits, or — better — see §6.

## 6. NEW: Own self-hosted meeting bot — free AgentCall replacement 🤖

Built `/ownbot` using the same technology AgentCall itself uses, running entirely on this machine at **zero cost**:

### How it works
- **Playwright launches a visible Chrome** that joins the Teams / Meet / Zoom call as a guest named "Aarav".
- Before the meeting page loads, injected JS overrides the media devices:
  - **Webcam** → live animated avatar canvas (blinks, mouth syncs to speech)
  - **Microphone** → WebAudio destination fed by **free Microsoft Edge neural TTS** (`en-IN-PrabhatNeural`)
- **Ears:** hooks `RTCPeerConnection`, taps every remote audio track (with the Chrome quirk handled — remote tracks only feed WebAudio when attached to a muted `<audio>` element), VAD-segments utterances, transcribes with **Groq Whisper**.
- **Brain:** the exact same Aarav logic as in-app — trigger word → command → HIL read-back → "confirm" — driving the shared screen via the existing `/?present=1` present-state.
- **Screenshare:** a second tab pinned to the title "Aarav Presents", auto-picked by Chrome capture flags (`POST /ownbot/share`).

### Files
- `backend/services/meetbot.py` — the browser bot + media injection script
- `backend/routers/ownbot.py` — `POST /ownbot/start`, `GET /ownbot/status`, `POST /ownbot/share`, `POST /ownbot/say`, `DELETE /ownbot` + the brain bridge
- Frontend 📹 button tries the own bot first, falls back to AgentCall only if the own bot can't launch
- `requirements.txt`: added `playwright`, `edge-tts` (plus `python -m playwright install chromium`)

### Verified end-to-end
A fake-meeting harness (real WebRTC loopback carrying synthesized speech) proved the whole loop: the bot's fake cam/mic were accepted → remote audio tapped → *"Aarav, please show the overdue assignments"* was heard → Whisper transcribed it → the brain ran it → **the shared app screen switched to the tracker filtered to overdue** → the bot spoke its reply.

**First real-world use:** the bot successfully joined a real Google Meet and waited in the lobby. Lesson learned → step 2 below.

### How to demo
1. Click **📹** in Aarav's panel → paste the meeting link. A Chrome window opens and asks to join.
2. **In the meeting, click *Admit*** when "Aarav" appears in the lobby ← don't skip this!
3. Say *"Aarav, give us a tour"*, *"Aarav, show the overdue assignments"*, *"Aarav, approve Chen Wei's request"* → *"confirm"*.
4. To put the app on screen: `POST /ownbot/share`, or click Share in the bot's Chrome window and pick the **"Aarav Presents"** tab.
5. Done? Tell in-app Aarav *"stop the bot"* — or just click 📹 again with a new link (it auto-replaces the old bot; no more "already running" error).

### Honest limitations
- The bot's Chrome window must stay open on this machine; someone must admit it from the lobby.
- Teams/Meet occasionally change their join screens — the join automation has fallbacks, and if it stalls you can finish clicking "Join" by hand in the bot's window; voice/ears/brain/camera keep working regardless.
- Zoom web join is often blocked by meeting settings; Teams and Meet are the reliable targets.
- No per-speaker diarization. No tunnel or paid API needed at all.
- **Do one real Teams/Meet dry run before the showcase** — join-screen selectors are the only part a local test can't cover.
